# 博客文章多语种化

## 概览

将一个 Hugo page bundle 文章本地化为目标语种。
如果 `index.<target-lang>.md` 不存在，则创建它；如果已存在，则输出优化后的版本并原地替换。

## 输入

要求用户准确提供两个输入：

- 博客文章目录，例如 `content/posts/2026/humans-job-in-the-future-will-be-to-press-enter-for-ai`
- 目标语言代码，例如 `en`、`zh-cn`、`ja`

把文章目录视为工作单元，而不是单个 markdown 文件。

## 工作流

1. 检查目录，找出所有 `index.*.md` 文件。
2. 将目标语种映射为 `index.<target-lang>.md`。
3. 除非用户明确指定参考的源语言或源文件，否则默认把同目录下所有非目标语种文章都作为参考。
4. 如果目标文件不存在，则基于可用源文章翻译并创建。
5. 如果目标文件已存在，则把它当作可编辑草稿，对照其它语种文章修正遗漏、误译和表达问题，然后原地覆盖。
6. 严格保留文章结构和资源，完成后再通读一次最终 markdown。

## 翻译准则

- 保留原意。只有在不改变作者意图、且能提升目标语言读者可读性的前提下，才修正明显的语法、措辞或流畅度问题。
- 如果用户明确要求“更像目标语言原生博客”或类似效果，可以在不新增事实、不改变结构的前提下，做轻度风格化改写，让标题、导语和过渡句更符合目标语种常见博客写法。
- 在合适的情况下，翻译 front matter 值和正文中的自然语言文本。
- 保留 front matter 的键名、结构和非文本值。
- 保留 shortcode 结构、markdown 排版、标题、提示块、列表、代码块、HTML 块和空行节奏。
- 除非某个字段本身需要翻译，否则保留所有图片、文件名、说明文字、链接和资源引用。
- 尽可能保留粗体、斜体、行内代码等强调样式。
- 不要新增原文没有的观点、例子、解释或总结。
- 不要静默省略任何内容，包括 caption、注释、表格，以及 shortcode 内的 alt/title 文本。

## Front Matter 规则

- 保持与作为结构基线的源文章相同的 front matter 字段集合和整体顺序。
- 在需要时翻译 `title`、`description` 以及其它面向读者的文本字段。
- 除非现有目标语种文件已经明确体现出仓库需要语言特化值，否则保持非语言型字段不变。
- 保留布尔值、日期、slug、图片文件名和功能开关，除非同目录其它语种文章明确体现出有意的语言差异。

## 多源参考规则

- 当存在多个非目标语种文件时，编辑前先全部阅读。
- 把它们视为同一篇文章的平行见证，而不是彼此独立的文章。
- 在处理歧义时，优先采用多个源语言共同表达的内容。
- 如果某个源版本更完整、另一个更流畅，可以综合使用，以产出更忠实的目标语种文章。
- 如果多个源版本在内容上存在实质冲突，先停下来询问用户哪个语种版本应作为权威来源。

## 保真检查清单

在写出最终文件前，确认以下事项：

- 目标文件仍位于同一个文章目录内。
- markdown 结构与源文章逐节对应。
- 每个 shortcode 和 HTML 块都仍然存在，且除可见文本翻译外，其参数保持不变。
- 每个本地资源引用仍然指向同一个文件名。
- front matter 仍包含预期字段和对格式敏感的值。

## 项目说明

在这个仓库里，如果文章位于 `content/posts/` 下，编辑前先阅读 `references/project-conventions.md`。
